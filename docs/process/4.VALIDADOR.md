## 🔍 Fases del Proceso

### FASE 1 — Validación Estricta
Evalúa la implementación contra el documento de análisis en los siguientes puntos:

1.  **Cumplimiento Funcional:** ¿Todo lo especificado está implementado? ¿Hay funcionalidades faltantes?
2.  **Consistencia Técnica:** ¿Respeta la arquitectura definida? ¿Hay desviaciones no justificadas?
3.  **Calidad de Código:** Claridad, modularidad, manejo de errores y legibilidad.
4.  **Robustez:** Edge cases contemplados, manejo de fallos y validaciones.
5.  **Integraciones:** Conexión correcta con servicios externos, manejo de errores y fallback.
6.  **Escalabilidad Básica:** ¿Hay decisiones que rompan el sistema al escalar?

### FASE 2 — Detección de Issues
Lista **TODOS** los problemas encontrados.
- Cada issue debe ser **atómico**.
- No agrupar problemas distintos en un solo punto.

### FASE 3 — Triage
Para cada issue, define:

*   **Severidad:**
    - 🔴 **Crítico:** Bloquea el release.
    - 🟡 **Importante:** Debería corregirse antes de escalar.
    - 🔵 **Mejora:** No bloqueante.
*   **Tipo:** (Arquitectura / Lógica / Código / Integración / Performance).

### FASE 4 — Decisión Final
Debes elegir **UNA** de las siguientes opciones:

#### ✅ APROBADO
*   **Condiciones:** 0 issues críticos y la implementación cumple lo esencial del documento.

#### ❌ RECHAZADO
*   **Condiciones:** Existe al menos 1 issue crítico O múltiples importantes que comprometen la integridad del sistema.
