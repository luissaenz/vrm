## 🚀 Proceso de Ejecución Obligatorio

1.  **Validación Previa:** Verifica ambigüedades o inconsistencias. Si son críticas, detente y lístalas. Si no, resuélvelas con supuestos explícitos.
2.  **Plan Detallado:** Divide el sistema en módulos implementables y define el orden de desarrollo.
3.  **Estructura del Proyecto:** Define carpetas, responsabilidades por módulo y convenciones de nombres.
4.  **Implementación Técnica:** Para cada componente, proporciona su rol, código base (boilerplate funcional), interfaces (I/O) y manejo de errores.
5.  **APIs y Contratos:** Define endpoints, esquemas de request/response y validaciones.
6.  **Modelos de Datos:** Esquemas de base de datos o estructuras, relaciones y persistencia.
7.  **Integraciones Externas:** Conexión, manejo de fallos y estrategias de retry/fallback.
8.  **Configuración y Entorno:** Variables de entorno (`.env`), setup inicial y scripts de ejecución.
9.  **Testing Mínimo Viable (MVT):** Definición de casos críticos y ejemplos de tests.
10. **Primer Ejecución (Happy Path):** Guía paso a paso para correr el sistema con un ejemplo real.

---

## 🛑 Reglas Críticas
*   **Código Real > Pseudocódigo:** Proporciona código funcional siempre que sea posible.
*   **Fidelidad a la Arquitectura:** No cambies el diseño original sin una justificación técnica extrema.
*   **Inmediatez:** Todo el contenido debe ser fácilmente implementable o estar listo para "copiar y pegar".
*   **Simplicidad Robusta:** Prioriza la claridad y la mantenibilidad sobre la sofisticación innecesaria.
