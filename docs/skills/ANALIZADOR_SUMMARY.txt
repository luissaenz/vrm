📦 QUÉ SE CREÓ
─────────────────────────────────────────────────────────────────────────────
Skill interactivo que transforma el proceso manual de ANALISIS.txt en un
comando automatizado que:

✅ Pide documento a analizar
✅ Pide sección específica
✅ Ejecuta análisis exhaustivo (10 secciones)
✅ GUARDA en carpeta original del documento
✅ Versionado automático (no sobrescribe)
✅ Nombre: [agente]-analisis.md


🎯 DIFERENCIA CON v1.0
─────────────────────────────────────────────────────────────────────────────
v1.0 (ANTIGUO):
  ❌ Referencias hardcodeadas a docs/, FASE_1/, etc.
  ❌ Múltiples archivos intermedios
  ❌ Guardado en ubicación fija

v1.5 (/ANALIZADOR - NUEVO):
  ✅ Agnóstico de ruta (funciona con cualquier documento)
  ✅ GUARDA en carpeta original del documento
  ✅ Versionado automático
  ✅ UN archivo de salida por ejecución

🚀 CÓMO USAR /ANALIZADOR
─────────────────────────────────────────────────────────────────────────────

Paso 1: Invoca el comando
  /Analizador

Paso 2: Responde 3 preguntas
  1. ¿Documento a analizar?
     → docs/mvp-Definition.md

  2. ¿Qué sección?
     → FASE 1

  3. ¿Confirmas?
     → SÍ

Paso 3: Sistema genera análisis
  [Ejecuta proceso ANALISIS.txt]
  [10 secciones exhaustivas]

Paso 4: Archivo guardado
  [seccion]-analisis-claude.md ✅


📊 SALIDA: DÓNDE SE GUARDA
─────────────────────────────────────────────────────────────────────────────

DOCUMENTO ORIGINAL:
  docs/mvp-Definition.md
  Sección: FASE 1
        ↓
ARCHIVO ANÁLISIS (mismo lugar):
  docs/FASE_1-analisis-claude.md

DOCUMENTO ORIGINAL:
  FASE_1/Dia4-5/especificacion.md
  Sección: Grabación de Video
        ↓
ARCHIVO ANÁLISIS (mismo lugar):
  FASE_1/Dia4-5/Grabacion_Video-analisis-claude.md

PATRÓN: [seccion]-analisis-[agente].md

REGLA: El análisis se guarda SIEMPRE en la misma carpeta que el documento


🔄 VERSIONADO AUTOMÁTICO
─────────────────────────────────────────────────────────────────────────────

Primera ejecución:
  /Analizador
  Documento: docs/mvp-Definition.md
  Sección: FASE 1
  → [seccion]-analisis-claude.md

Segunda ejecución (misma sección):
  /Analizador
  Documento: docs/mvp-Definition.md
  Sección: FASE 1
  → docs/claude-analisis(1).md ✓ (automático)

Tercera ejecución:
  → docs/claude-analisis(2).md ✓ (automático)

CARACTERÍSTICAS:
  ✓ No sobrescribe archivos existentes
  ✓ Mantiene historial de análisis
  ✓ Puedes comparar versiones
  ✓ Automático (sin intervención)


📋 CONTENIDO DEL ANÁLISIS (10 SECCIONES)
─────────────────────────────────────────────────────────────────────────────

El archivo generado contiene exactamente lo que pide ANALISIS.txt:

  1. COMPRENSIÓN DEL PASO
     • ¿Qué problema resuelve?
     • ¿Qué inputs recibe?
     • ¿Qué outputs debe generar?
     • ¿Qué rol cumple?

  2. SUPUESTOS Y AMBIGÜEDADES
     • TODO lo no definido
     • Preguntas críticas
     • Lo que debe resolverse antes

  3. DISEÑO FUNCIONAL
     • Flujo completo paso a paso
     • Casos normales
     • Edge cases
     • Manejo de errores

  4. DISEÑO TÉCNICO
     • Arquitectura sugerida
     • Componentes involucrados
     • APIs / endpoints necesarios
     • Modelos de datos (schemas)
     • Integraciones externas

  5. DECISIONES TECNOLÓGICAS
     • Lenguajes / frameworks
     • Librerías clave
     • Justificación técnica

  6. PLAN DE IMPLEMENTACIÓN
     • Tareas pequeñas (backlog)
     • Orden de desarrollo
     • Dependencias

  7. RIESGOS Y CUELLOS DE BOTELLA
     • Técnicos
     • Operativos
     • Escalabilidad
     • Costos

  8. MÉTRICAS DE ÉXITO
     • Cómo validar que está bien
     • KPIs técnicos y negocio

  9. ESTRATEGIA DE TESTING
     • Unit tests
     • Integration tests
     • Casos críticos

  10. OPTIMIZACIÓN Y ESCALABILIDAD FUTURA
      • Problemas al escalar
      • Preparación desde ahora


✨ CARACTERÍSTICAS ESPECIALES
